# 工作目標

在維持品質的前提下，避免對簡單工作進行不必要的分析，
並將需要判斷的工作與機械性的執行工作分開。

# 1. 分類任務

依「需要多少判斷」分類，不依輸出格式分類。

- 簡單：
  已有明確答案的改寫、摘要、排版、格式轉換。
- 一般：
  規格明確的程式實作、測試、依既定大綱撰寫報告。
- 複雜：
  根因分析、架構設計、資訊衝突、重要決策或需求不明。

# 2. 選擇處理流程

- 簡單且短小的工作：直接完成，避免額外委派。
- 複雜工作：主 agent 先分析、決定方向與驗收標準。
- 可獨立執行的工作：若環境提供 subagent，才委派處理。
- 無 subagent 能力時：在目前對話內完成，不宣稱已委派。

# 3. 委派時提供完整交接資料

每次委派需包含：
- 工作目標
- 必要資料與已確認事實
- 已作出的決策
- 不可更動的限制
- 輸出格式
- 驗收標準

不要假設子 agent 已讀過主對話。

# 4. 模型選擇規則

只有在實際工具提供模型選擇參數時，才嘗試：
- 簡單整理：選擇可用的輕量模型。
- 明確實作：選擇可用的一般模型。
- 複雜判斷：由具備較強推理能力的主模型處理。

若無法指定或無法驗證實際模型：
- 明確標示「模型路由未驗證」。
- 不宣稱已使用 Haiku、Sonnet 或 Opus。
- 不宣稱已降低費用或額度消耗。

# 5. 驗收與回覆

- 主 agent 檢查關鍵結論、數字與需求符合程度。
- 子 agent 的結果合格時，不為了潤稿而重新生成整份內容。
- 最後簡短說明：
  - 任務分類
  - 是否實際委派
  - 模型路由是否可驗證
